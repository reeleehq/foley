foley.eval.panel#

Human-panel infrastructure: blind tasks, a listening page, responses, and the calibration feed (#49).

A model judge is only trusted once it agrees with people (foley.eval.reliability). This module is the manual-first path that produces those people’s judgements; the panel itself is run by a person. Three task kinds, one flow:

  1. Build blind tasks from what you want judged: grade_tasks() (rate one clip 0-3 for a prompt: the scale the judge-vs-human α uses), pairwise_tasks() (2AFC: which of two fits better; feeds foley.eval.bradley_terry), mushra_tasks() (rate several systems 0-100 against a reference, with a hidden copy of the reference and a low anchor, in the style of ITU-R BS.1534). Sides and order are shuffled with a seed; stimulus ids are opaque. save_tasks() copies every clip to audio/<stimulus id><ext> (so neither a file name nor the hidden reference’s path gives it away) and writes tasks.json (what raters get) and key.json (which system each stimulus is; keep it from the raters).

  2. Run it: render_panel_html() writes one self-contained page (audio, forms, a “download responses” button) to open in a browser or host anywhere static; or send tasks.json to raters and collect the same responses.jsonl by any means. A response is one JSON line: {"rater": ..., "task": ..., "answer": ...} (the answer shape is per kind, see check_answer()).

  3. Analyse: pairwise_comparisons() -> bradley_terry.fit; screen_mushra() (the hidden-reference rule of ITU-R BS.1534 only; the standard’s

    mid-range anchor rule is not implemented) and mushra_scores(); rating_units() ->

    calibrate_against_judge(), which returns the human-human and judge-vs-human

    Krippendorff α (foley.eval.reliability.calibrate_judge_vs_human()) to put in the calibration report.

Pure stdlib apart from the numpy used in the analysis functions.

foley.eval.panel.calibrate_against_judge(units, judge_grades, *, level='ordinal', min_raters=3, min_units=50)[source]#

Human-human and judge-vs-human agreement, ready for the calibration report.

The judge is compared with the humans’ consensus (the per-unit median grade), never as one more rater next to all of them: with many humans who agree with each other, a judge added as a row would borrow their agreement and look reliable whatever it says. per_rater is α of the judge against each person alone.

Parameters:

  • units (Mapping[str, Mapping[str, int]]) – rating_units()’ {unit: {rater: grade}}.

  • judge_grades (Mapping[str, int]) – The model judge’s {unit: grade} for the same units.

  • min_raters (int) – Fewer raters than this and nothing is promoted.

  • min_units (int) – Fewer units rated by at least two people than this and nothing is promoted.

Returns:

AlphaResult | None, “judge_vs_human”: AlphaResult | None, “per_rater”: {rater: alpha}, “n_units”: …, “raters”: […], “insufficient”: […]}``. human_alpha is the humans’ own α (it needs two raters and a unit both rated); judge_vs_human is the judge against the consensus. An AlphaResult is never promoted while insufficient is non-empty: too few raters, too few doubly-rated units, or human (or judge) grades that do not vary (α is 1 by construction then).

Return type:

dict

foley.eval.panel.save_tasks(tasks, key, directory, *, audio_dir='audio')[source]#

Write the panel folder: tasks.json (for raters), key.json (keep private), the audio.

Every clip (a local file) is copied to <directory>/<audio_dir>/<stimulus id><ext> and the tasks written point at the copies, so a file name never names the system and the hidden reference does not share a path with the visible one. The returned tasks are those rewritten ones (hand them to foley.eval.panel_page.render_panel_html()).

Raises:

  • FileNotFoundError – A clip is not a local file (fetch it first).

  • ValueError – Task ids repeat, or the clips are in more than one format (the extension would give a system away).

Return type:

tuple[Path, Path, list[Task]]
