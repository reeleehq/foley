foley.index.onnx_clap#

CLAP on a small host: the same checkpoint through ONNX Runtime, no torch, no transformers.

A production server with no GPU, about 2 GB of free RAM and no transformers cannot load ClapEmbedder (a ~1.7 GB model plus torch), so every generated clip there used to be unchecked by foley.prompt_match.prompt_match() (#116). OnnxClapEmbedder runs laion/larger_clap_general from the community ONNX export Xenova/larger_clap_general (ungated), int8-quantised: about 205 MB on disk, a few hundred MB of RAM, and the same 512-d text-audio space, so it can stand in for the full model wherever only the similarity of a text and a clip matters.

It needs onnxruntime, tokenizers and huggingface_hub (the foley[clap-onnx] extra) and numpy; the log-mel front end is a small numpy port of transformers’ ClapFeatureExtractor (checked against it in the tests), so nothing else is imported. The quantised model gives slightly different vectors from the full one: its prompt-match threshold is calibrated separately (foley.eval.prompt_match) under its own id, ONNX_CLAP_MODEL_ID, and it is not a drop-in for an index built with the full embedder (use it to compare a text with a clip, not to search an index).

Same protocol as ClapEmbedder: embed_text -> (n, 512), embed_audio -> (512,), L2-normalised, prompt_match_threshold. Clips over 10 s are cut to the middle 10 s (transformers takes a random crop), so the vector is deterministic.

foley.index.onnx_clap.log_mel(wav)[source]#

The (1001, 64) dB log-mel features of a mono 48 kHz clip, as ClapFeatureExtractor’s.

The clip is cut to its middle 10 s or, if shorter, repeated to fill 10 s and zero-padded (repeatpad); then a centred, reflect-padded, periodic-Hann STFT (1024 / hop 480), power spectrum, mel projection, 10 * log10(max(x, 1e-10)).

Return type:

ndarray
