foley.sources.media#

Media inputs of generation (#74, #162, #215): what video= and an edit’s audio= may be, and their identity.

A backend that sounds a picture (video-to-audio) takes a video=; a backend that edits a source clip takes an audio=. Both are media inputs (MEDIA, MEDIA_INPUTS) and take the same forms: a URL (http(s):// or a data: URI, sent as is), a RemoteVideo (a URL with the SHA-256 of its content), a local path, or raw bytes (both uploaded by the backend’s adapter). These questions are answered here, once, for every media input:

  • media_key(): what the generations cache keys the input as. The content (sha256:<hex> of the bytes, the file or a RemoteVideo’s digest), never its path, so a moved file hits the cache and an edited one cannot; a bare remote URL is keyed as the URL.

  • is_media_key(): whether a value is already such a key (as a cache entry keeps it).

  • replayable(): whether an identical request may be served from the cache. Not for a bare remote URL: the content behind it may have changed (#173).

  • recorded_media_key(): the key as it is written down (a cache entry, a run manifest, a licence): a bare URL without its query, fragment or credentials, so a presigned URL’s token never reaches a record (#184). The request digest still hashes media_key().

  • media_url(): the URL a backend fetches the input from itself, if it is one.

  • local_media_file(): a local file for an uploader (bytes are written to a temporary file whose suffix is sniffed from them: video_suffix(), or the input’s own sniffer, MediaInput.suffix()).

  • keyed(): affordances as they may be recorded (the cache entry, the run manifest): each media input replaced by its recorded key, so neither its bytes nor a local path (nor an upload’s capability URL, nor a presigned URL’s token) is written down.

Each media input is one row of MEDIA (its mode, its upload suffix sniffer, its length probe): a video’s suffix is sniffed by video_suffix() and its length read by foley.sources.video.video_seconds(); an edit’s source clip’s by audio_suffix() and audio_seconds().

What only a video has (its length by ffprobe/mixing, the audio track of a muxed answer) is in foley.sources.video, which also keeps this module’s helpers importable under their former video_* names.

Stdlib only (soundfile and falaw are used when installed, never required).

class foley.sources.media.RemoteVideo(*, url, sha256)[source]#

Bases: object

A remote video url with the SHA-256 of its bytes: keyed, and replayed, by content.

A bare https:// URL is keyed as the URL, which foley cannot see behind, so an identical request for it is never served from the generations cache (the picture may have changed: .../latest.mp4). A caller who knows the content passes this instead, and a repeat is replayed while the digest is the same (#173).

The digest is trusted, not checked (foley does not fetch the URL): it is recorded as the input’s identity in the cache key and the licence’s generation_params, as a digest foley computed would be.

>>> RemoteVideo(url="https://x/clip.mp4", sha256="sha256:" + "ab" * 32).sha256[:4]
'abab'
>>> RemoteVideo(url="clip.mp4", sha256="ab" * 32)
Traceback (most recent call last):
...
ValueError: RemoteVideo.url must be an http(s) URL, got 'clip.mp4'

foley.sources.media.recorded_media_key(media)[source]#

media_key() as it is written down: a bare URL keeps its scheme, host and path only (#184): its query, fragment and ; path parameters (a presigned URL’s signature, a session id) become REDACTED_QUERY, and credentials before the host are dropped. Two URLs that differ only there record (and are found by find()) as one, as a re-signed URL should. An already recorded or bare url: key is redacted the same way.

>>> recorded_media_key("https://u:p@bucket.s3.example/a.mp4?X-Amz-Signature=s3cr3t")
'url:https://bucket.s3.example/a.mp4?…'
>>> recorded_media_key("https://[::1]:8080/a.mp4;jsessionid=X#t=2")
'url:https://[::1]:8080/a.mp4?…'
>>> recorded_media_key("https://x/a.mp4"), recorded_media_key(b"abc")[:11]
('url:https://x/a.mp4', 'sha256:ba78')
Return type:

str

foley.sources.media.replayable(affordances, *, is_immutable=<function fal_immutable_url>)[source]#

Whether an identical request may be served from the cache (#173).

Not when a media input (MEDIA_INPUTS) is a bare remote URL whose content foley never saw, unless is_immutable(url) says it never serves other bytes (default: fal_immutable_url(), fal’s own CDN). Decided from the values alone: no file is read.

>>> replayable({"video": "https://x/latest.mp4"}), replayable({"video": b"abc"})
(False, True)
>>> replayable({"video": "https://x/a.mp4"}, is_immutable=lambda url: True)
True
>>> replayable({"seed": 1}), replayable({"audio": "https://x/take.wav"})
(True, False)

bool

foley.sources.media.video_suffix(data)[source]#

The file suffix of encoded video data, sniffed from its first bytes.

An uploader (and ffmpeg) names the format by the suffix, so a WebM written as .mp4 goes out mislabelled. Anything unrecognised is .mp4.

>>> video_suffix(b"\x00\x00\x00\x18ftypqt  \x00"), video_suffix(b"\x00\x00\x00\x18ftypisom")
('.mov', '.mp4')
>>> video_suffix(b"\x1a\x45\xdf\xa3\x9f\x42\x82\x84webm"), video_suffix(b"\x1a\x45\xdf\xa3")
('.webm', '.mkv')
>>> video_suffix(b"RIFF\x00\x00\x00\x00AVI "), video_suffix(b"OggS"), video_suffix(b"?")
('.avi', '.ogv', '.mp4')
