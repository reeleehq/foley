foley.sources.video#

Media inputs of generation (#74, #162): what video= (and an edit’s audio=) may be, its identity, its length.

A video-to-audio (V2A) backend takes the picture the sound must follow. foley accepts it as a URL (http(s):// or a data: URI, sent as is), a RemoteVideo (a URL with the SHA-256 of its content), a local path, or raw bytes (both uploaded by the backend’s adapter). These questions are answered here, once, for every V2A backend:

  • video_key(): what the generations cache keys the video as. The content (sha256:<hex> of the bytes, the file or a RemoteVideo’s digest), never its path, so a moved file hits the cache and an edited one cannot; a bare remote URL is keyed as the URL.

  • replayable(): whether an identical request may be served from the cache. Not for a bare remote URL: the content behind it may have changed (#173).

  • recorded_video_key(): the key as it is written down (a cache entry, a run manifest, a licence): a bare URL without its query, fragment or credentials, so a presigned URL’s token never reaches a record (#184). The request digest still hashes video_key().

  • video_seconds(): its length, for a backend priced per second of the video (probe=; default default_probe(): ffprobe on PATH, else mixing’s probe_duration through mixing’s ffmpeg resolver; None when it cannot be read, which prices the call as an unknown cost, needing approval).

  • has_audio_stream(): whether a media file has an audio stream (ffprobe, else soundfile; None when it cannot tell).

  • local_video_file(): a local file for an uploader (bytes are written to a temporary file whose suffix is sniffed from them: video_suffix()).

  • audio_track(): the audio of a backend’s muxed video answer (MMAudio, ThinkSound and HunyuanVideo-Foley return the video with the sound in it), via ffmpeg (ffmpeg_path()).

  • keyed(): affordances as they may be recorded (the cache entry, the run manifest): the video replaced by its recorded key, so neither its bytes nor a local path (nor an upload’s capability URL, nor a presigned URL’s token) is written down.

The source clip of an edit (audio=, #162) is a media input too (MEDIA_INPUTS): it takes the same forms, and is keyed, recorded and replayed by the same functions (keyed(), replayable()). Each media input is one row of MEDIA (its mode, its upload suffix sniffer, its length probe): the edit’s upload suffix is sniffed by audio_suffix() and its length read by audio_seconds().

Stdlib only (mixing and soundfile are used when installed, never required).

class foley.sources.video.RemoteVideo(*, url, sha256)[source]#

Bases: object

A remote video url with the SHA-256 of its bytes: keyed, and replayed, by content.

A bare https:// URL is keyed as the URL, which foley cannot see behind, so an identical request for it is never served from the generations cache (the picture may have changed: .../latest.mp4). A caller who knows the content passes this instead, and a repeat is replayed while the digest is the same (#173).

The digest is trusted, not checked (foley does not fetch the URL): it is recorded as the input’s identity in the cache key and the licence’s generation_params, as a digest foley computed would be.

>>> RemoteVideo(url="https://x/clip.mp4", sha256="sha256:" + "ab" * 32).sha256[:4]
'abab'
>>> RemoteVideo(url="clip.mp4", sha256="ab" * 32)
Traceback (most recent call last):
...
ValueError: RemoteVideo.url must be an http(s) URL, got 'clip.mp4'

foley.sources.video.has_audio_stream(path, *, ffprobe=None)[source]#

Whether the media file at path has an audio stream, or None when that cannot be told.

By ffprobe (default: the one on PATH; bounded by PROBE_TIMEOUT_S): True when it lists an audio stream, False when it lists none or cannot read the file (a video-only mp4, a gif, an error page), None when it cannot run or runs too long. Without ffprobe, by soundfile (the decoder foley.audio.load() uses): True when it decodes the file to one or more channels, else None (it reads no video container, so its refusal says nothing). A caller that needs an answer treats None as no (fail closed).

foley.sources.video.recorded_video_key(video)[source]#

video_key() as it is written down: a bare URL keeps its scheme, host and path only (#184): its query, fragment and ; path parameters (a presigned URL’s signature, a session id) become REDACTED_QUERY, and credentials before the host are dropped. Two URLs that differ only there record (and are found by find()) as one, as a re-signed URL should. An already recorded or bare url: key is redacted the same way.

>>> recorded_video_key("https://u:p@bucket.s3.example/a.mp4?X-Amz-Signature=s3cr3t")
'url:https://bucket.s3.example/a.mp4?…'
>>> recorded_video_key("https://[::1]:8080/a.mp4;jsessionid=X#t=2")
'url:https://[::1]:8080/a.mp4?…'
>>> recorded_video_key("https://x/a.mp4"), recorded_video_key(b"abc")[:11]
('url:https://x/a.mp4', 'sha256:ba78')

str

foley.sources.video.video_suffix(data)[source]#

The file suffix of encoded video data, sniffed from its first bytes.

An uploader (and ffmpeg) names the format by the suffix, so a WebM written as .mp4 goes out mislabelled. Anything unrecognised is .mp4.
